01 Machine Learning · Graph Neural Networks · User-Friendly Explainable AI ·

GNN Explainable Game
Recommendation System

Explainable Relational User Recommendations

Constructed a heterogeneous knowledge graph recommender from Steam game meta data and interaction data. Trained GraphSAGE and LightGCN in an ensemble on the knowledge graph to predict which games a user is likely to play next. Generated human-readable justifications for the recommendations with rule-based relational path extraction to find direct paths to the recommendations and GNNExplainer subgraph attributions to rank weights of the most important relations/edges.

Models
GraphSAGE

This model learns inductive aggregation functions by aggregating information from a node's neighbors in a way that generalizes to unseen neighborhoods.

LightGCN

Custom 3-layer implementation (128-dim) using only symmetric-normalized propagation with learnable per-edge-type weights — no weight matrices, no nonlinearities. Final embeddings are the mean across all layers, isolating pure collaborative-filtering signal from graph connectivity alone.

Both decode via dot-product scoring and train on a playtime-weighted BPR ranking loss.

Data

Steam-200k play interactions joined with FronkonGames Steam metadata (log1p-scaled playtime used as an engagement weight) to build a 7-node-type heterogeneous graph — each game node also carries 5 normalized numeric features (price, review volume/ratio, estimated owners, release year).

11,350 users 3,600 games 1,696 matched 70K plays 4.4K genre 1.9K developer 1.7K publisher 3.5K category 3.1K platform
Explainability
GNNExplainer

Learns a soft importance mask over a compact 2-hop subgraph (user → played/recommended games → genre/developer) by gradient-optimizing a frozen 2-layer GCN, surfacing which edges most shaped the embedding.

Relational Paths

Independently searches the full 17K-node knowledge graph for user → game paths (≤4 hops), ranks them by overlap with GNNExplainer's flagged nodes, and deduplicates by bridge entity to surface 3 diverse, human-readable justifications per recommendation.

Eval
ROC-AUC

Ranks positive vs. sampled-negative user-game pairs — robust to the interaction data's class imbalance.

Average Precision

Summarizes the precision-recall tradeoff — most informative when true positives are sparse relative to all possible pairs.

Hits@10

Full-ranking check: does each held-out game land in a user's top 10 out of all 3,600 games? The metric closest to real-world recommendation quality.

02 NLP Research · LLM Analysis · Fine-Tuning

Formality Bias in LLMs

Identifying and addressing formality bias in large language model outputs

A research project detecting, measuring, and mitigating a systematic formality bias in large language model outputs. Constructed two metrics to measure formality in LLM outputs: a lexicon-based Formality Rate (FR) that measures the formality of text through the rate of formal words in the corpus and a RoBERTa-based binary classifier. Compared 25 LLMs against three human conversational baselines using two complementary metrics. The finding: formality is model-agnostic — it's driven by conversational topic, not model architecture. Then we fixed it with LoRA.

Metrics Formality Rate (FR) — lexicon-based hits/1000 tokens; RoBERTa binary classifier score (bert_formal_p)
Corpus LMSYS-Chat-1M (25 models, real users) vs. BlendedSkillTalk, Reddit TIFU, ELI5
Classifier s-nlp/roberta-base-formality-ranker fine-tuned on Pavlick formality scores (GYAFC corpus)
Finding Formality bias is model-agnostic — driven primarily by conversational topic, not model family
Mitigation LoRA fine-tuning on Qwen2.5-3B-Instruct on low-formality data; evaluated with paired statistical tests

03 Computer Vision · Deep Learning · OCR

Handwritten
OCR System

From raw ink to corrected text, end-to-end

A full handwriting-to-text pipeline: an OpenCV segmentation stage extracts individual characters from full-word images, routes them through a ViT + CNN ensemble classifier, and post-processes the reconstructed output with SymSpell for spelling correction. Both models were trained and fine-tuned on a 400K-image handwritten character dataset published on Kaggle.

Segmentation OpenCV: Gaussian blur → adaptive thresholding → contour detection + dilation → bounding-box sort
Models ViT-B-16 (partial layer freeze, OneCycleLR) + 5-block CNN (CosineDecayRestarts, label smoothing 0.1)
Training tricks Class weighting (balanced), early stopping, custom classification heads, OneCycle + Cosine LR schedules
Post-processing SymSpell dictionary-based spell correction on reconstructed word output
Dataset 400K-image handwritten character set (Kaggle: warrenxnguyen/handwritten-letters)
