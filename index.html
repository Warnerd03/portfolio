01 ML · Graph Learning · Explainable AI

GNN Game
Recommender

Steam knowledge graph meets explainable AI

A heterogeneous knowledge graph recommender trained on real Steam interaction data, combining GraphSAGE and LightGCN in an ensemble to predict which games a user is likely to play next. The system doesn't just recommend; it explains why through subgraph attribution and human-readable relation paths.

Models GraphSAGE + LightGCN ensemble over a 7-node-type heterogeneous graph, blend weight tuned via validation-set grid search
Data Steam-200k interactions (11K+ users, 3.6K+ games) + Steam metadata (genres, devs, publishers, platforms) via HuggingFace
Explainability GNNExplainer subgraph attribution + rule-based relational path extraction (human-readable)
Eval Full-ranking test set: 0.92 ROC-AUC · 0.92 Average Precision · 0.35 Hits@10
Pipeline kagglehub + HuggingFace Datasets for ingestion · PyTorch Geometric for graph construction and modeling

02 NLP Research · LLM Analysis · Fine-Tuning

Formality Bias
in LLMs

Quantifying what language models won't say casually

A research project detecting, measuring, and mitigating a systematic formality bias in large language model outputs. Compared 25 LLMs against three human conversational baselines using two complementary metrics. The finding: formality is model-agnostic — it's driven by conversational topic, not model architecture. Then we fixed it with LoRA.

Metrics Formality Rate (FR) — lexicon-based hits/1000 tokens; RoBERTa binary classifier score (bert_formal_p)
Corpus LMSYS-Chat-1M (25 models, real users) vs. BlendedSkillTalk, Reddit TIFU, ELI5
Classifier s-nlp/roberta-base-formality-ranker fine-tuned on Pavlick formality scores (GYAFC corpus)
Finding Formality bias is model-agnostic — driven primarily by conversational topic, not model family
Mitigation LoRA fine-tuning on Qwen2.5-3B-Instruct on low-formality data; evaluated with paired statistical tests

03 Computer Vision · Deep Learning · OCR

Handwritten
OCR System

From raw ink to corrected text, end-to-end

A full handwriting-to-text pipeline: an OpenCV segmentation stage extracts individual characters from full-word images, routes them through a ViT + CNN ensemble classifier, and post-processes the reconstructed output with SymSpell for spelling correction. Both models were trained and fine-tuned on a 400K-image handwritten character dataset published on Kaggle.

Segmentation OpenCV: Gaussian blur → adaptive thresholding → contour detection + dilation → bounding-box sort
Models ViT-B-16 (partial layer freeze, OneCycleLR) + 5-block CNN (CosineDecayRestarts, label smoothing 0.1)
Training tricks Class weighting (balanced), early stopping, custom classification heads, OneCycle + Cosine LR schedules
Post-processing SymSpell dictionary-based spell correction on reconstructed word output
Dataset 400K-image handwritten character set (Kaggle: warrenxnguyen/handwritten-letters)
